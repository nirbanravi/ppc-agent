How to stop AI agents from changing your ad account

AI agents can now act on ad accounts through MCP servers, and several official servers can create, edit and delete. Here's how SpendSentry makes every change go through you.

The risk

A model that is confidently wrong about a budget, a bid strategy or a pause can cost a month's spend in an afternoon. Asking the model to be careful isn't enough; the protection needs to be enforced in code, outside the model.

The approval gate

  1. Propose. Claude writes exact actions: before and after values, rollback, and the audit finding IDs that justify each one.
  2. Gate. Checks run in code: data no older than 72 hours, account on your allow-list, budget change within ±30%, bid change within ±25%, no deletes, new campaigns created paused, evidence exists, rollback defined.
  3. Approve. You see the list and a code such as ADS-C15127. You approve by sending APPROVE ADS-C15127.
  4. Execute once. The guard lets each approved call through exactly once, and only with the approved input. Replays, edited inputs, edited changesets and expired approvals are blocked.

FAQ

Can AI agents change my Google or Meta ad account?

Yes, if they are connected to a write-capable tool. Meta's hosted Ads MCP server and the Amazon Ads MCP Server both support creating, updating and deleting. Google's official Google Ads MCP server is read-only.

How does SpendSentry stop unapproved changes?

A Claude Code PreToolUse hook checks every ad-platform tool call. Write-capable calls are blocked unless the exact tool and input match an action in a changeset that passed safety checks and that you approved by typing a one-time code.

Can the AI approve its own changes?

No. Approvals are recorded only from your own message, by a separate hook. Attempts to write an approval file, type the approval phrase in a command, or send raw HTTP writes to ad APIs are blocked.

What are the limits of this protection?

Shell-level detection is pattern-based, so keep ad API credentials out of your shell environment. Skill hooks start when the skill is loaded; installing it as a plugin keeps them active whenever the plugin is enabled.
